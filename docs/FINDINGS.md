# 分析結果サマリ（2025年 第3回プロトフェス）

**このファイルだけ読めば設計判断ができるように書いてある。**
数値の出典は `output/metrics.json`、算出定義は [specs/analytics-pipeline/04-analysis/metrics-catalog.md](specs/analytics-pipeline/04-analysis/metrics-catalog.md)。

| 項目 | 値 |
|---|---|
| 対象イベント | 第3回プロトフェス 2025-10-10(金)・10-11(土) の2日間 |
| データ源 | GCP `protofes` / Firestore `(default)` |
| 抽出日時 | 2026-08-18 01:40 JST |
| 分析単位 | **ユーザー × 日**（両日参加者の滞在時間が24時間超になるのを防ぐため） |
| タイムゾーン | 全て **JST(UTC+9)** に変換済み |
| 除外 | イベント期間外の27件（5名分）のみ。運営・出展者の除外は**未実施** |

---

## 0. 先に読むべき制約（これを外すと結論を誤る）

| # | 制約 | 影響 |
|---|---|---|
| 1 | **滞在時間は真の値の下限** | 入退場記録がなく「最終CI − 初回CI」で代用。受付→初回、最終→退場のラグが失われる。「30分未満がX%」は真の値ではX%より**小さい** |
| 2 | **チェックイン間隔はクールタイム制約に張り付いている（22.0%）** | 事前基準の「20〜30%以上」に該当。**訪問ペースの中央値は下限としてのみ使用可。「後半にペースが落ちるか」は結論を出せない** |
| 3 | **推薦効果は位置効果と交絡** | 推薦マスは中央4マス(position 5/6/9/10)固定。中央が目立つから踏まれた可能性を排除できない |
| 4 | **302名は2日間の延べ** | 今年の見積もり(150〜200名)と直接比較禁止。**金曜のみの192名**と比べること |
| 5 | **同一ブースへの再訪問は記録されない** | 「ユニーク訪問数」と「チェックイン総数」は構造上つねに一致。再訪問分析は不可能 |
| 6 | **運営・出展者が除外されていない** | 候補は `u0283`(34ブース)の1名のみ。除外すると判断4が変わりうる（後述） |

## 1. 五つの問いへの回答

| # | 問い | 回答 | 根拠値 |
|---|---|---|---|
| 1 | 典型像は「短時間・数ブース」か「長時間・多ブース」か | **二層構造**。単一の典型像は存在しない | 金曜の30分未満 **37.0%** |
| 2 | 今年のデータ件数規模 | **900〜1,200件**。協調フィルタリングの成立ラインぎりぎり | 想定150〜200名 × 中央値6.0ブース |
| 3 | 推薦が届く対象 | **約3人に1人には構造的に届かない**。推薦と並行して初回体験を改善すべき | 金曜 **31.8%**（0件50名＋単発27名） |
| 4 | ブース偏りへの対策コスト | **偏りは深刻。ただし判定は境界上** | 最多/最少 **5.12倍**（しきい値5.0） |
| 5 | データが溜まり始めるタイミング | **開場直後は推薦に使えるデータがない。初期はランダム提示が必要** | 新規流入ピークは開場4時間後の13:30 |

## 3. 判断1 — 参加者の典型像

**判定: 二層構造。短時間層と長時間層で別々の体験設計が要る。**

| しきい値（事前固定） | 判断 | 該当 |
|---|---|:-:|
| 30分未満が50%以上 | 短時間層が多数派 | |
| **30分未満が20〜50%** | **二層構造** | ✅ |
| 30分未満が20%未満 | 長時間滞在が標準 | |

| 滞在時間（分） | 金 | 土 |
|---|---:|---:|
| 中央値 | **64.5** | 58.4 |
| 平均 | 84.4 | 69.3 |
| Q1 | 29.3 | 34.2 |
| Q3 | 114.1 | 95.9 |
| 30分未満の割合 | **37.0%** | 32.0% |
| 3時間以上の割合 | 11.5% | 2.3% |
| 単発訪問者（滞在時間0） | 27名 (14.1%) | 15名 (14.6%) |

- 中央値・四分位は**単発訪問者を除外**して算出（0が大量に混入すると分布が壊れるため）
- 30分未満の割合は**単発訪問者を分母に含める**（「短時間で帰った層」の実態を示すため）
- 金曜は3時間以上が11.5%あるのに対し土曜は2.3%。**土曜は長時間層が薄い**

## 4. 判断2 — 今年のデータ件数規模

**判定: 境界。参加者175名以上なら協調フィルタリングが成立する。**

```
今年の想定チェックイン数 = 今年の想定参加者数 × 去年金曜の中央値 6.0ブース
```

| 今年の参加者数 | 想定チェックイン数 | 判断 |
|---:|---:|---|
| 150名 | 900件 | 限界的。人気度ベースに留める |
| **175名** | **1,050件** | 協調フィルタリングが機能する |
| 200名 | 1,200件 | 協調フィルタリングが機能する |

しきい値は 1,000件以上=CF妥当 / 300〜1,000件=人気度ベース / 300件未満=ルールベース。

**注意**: 去年の総数2,141件は2日間の値。必ず金曜のみ（1,367件・192名）から外挿すること。

**滞在時間あたりの訪問ペース: 1.66 ブース/時間**（金曜・単発訪問者を除く回帰、n=165）。
規模見積もりで最も再利用される数字だが、**制約2により下限値**として扱うこと。

## 5. 判断3 — 推薦が届く対象

**判定: 推薦は有効だが、初回体験の改善と並行して進める。**

推薦は「2件目以降のチェックイン」でしか意味を持たないため、以下の層には**構造的に届かない**。

| 層 | 金曜 | 土曜 |
|---|---:|---:|
| チェックイン0件 | 50名 | 50名 |
| 単発訪問者（1ブースのみ） | 27名 | 15名 |
| **合計 / 分母** | **77 / 242 = 31.8%** | 65 / 153 = 42.5% |

| しきい値（事前固定） | 判断 | 該当 |
|---|---|:-:|
| 合計40%以上 | 「使われない問題」が先。オンボーディング優先 | （土曜は該当） |
| **合計20〜40%** | **推薦は有効だが初回体験の改善と並行** | ✅（金曜） |
| 合計20%未満 | 推薦機能に集中してよい | |

**チェックイン0件の50名は日に紐づかない**ため、両日の分母に重複して現れる。
全期間で見ると（0件50名＋全日単発34名）/ 302 = **27.8%**。

## 6. 判断4 — ブース間の訪問偏り

**判定: 偏りは深刻。ただし 5.12倍はしきい値5.0の境界上であり、確定前に運営アカウントの除外が必要。**

| 指標 | 値 | しきい値 | 判定 |
|---|---:|---|---|
| 最多/最少の倍率 | **5.12倍** | 5倍以上で深刻 | ⚠️ 深刻（境界） |
| 最多訪問者数 | 128名 | | |
| 最少訪問者数 | 25名 | | |
| 上位20%(8ブース)の占有率 | 30.4% | 50%以上で対策対象 | ✅ 該当せず |
| 訪問者0のブース | 0件 | | 全40ブースが最低25名を集めた |

**倍率は「深刻」だが占有率は「該当せず」で、2つの基準が食い違っている。**
上位が突出している一方で全体としての集中度は低い、という形。
`u0283`(34ブース訪問)を除外すると倍率が5.0を下回る可能性があるため、
**除外規則2の目視確定を先に済ませること。**

| 順位 | ブース | 訪問者数 |
|---:|---|---:|
| 1 | ㊵ hajime coffee | 128 |
| 2 | ㊴ 移動式フォトスポット | 100 |
| 3 | ③ 転売ヤー対策 広告生成 出品機能『Reseller…』 | 81 |
| 4 | ㊳ PRoToFES BINGO | 73 |
| 5 | ㉞ タッチパネル | 68 |
| … | | |
| 38 | ㉚ 海洋プラ→フライングディスク | 35 |
| 39 | ⑳ ハナサnightカフェ | 31 |
| 40 | ㉘ 課外活動記録のブロックチェーン永続化 | 25 |

会場マップ上の座標は存在しないため「入口からの距離との関係」は未算出。
手入力（40ブース・約30分）が必要。**偏りが境界的なので、着手は判断4の確定後**。

## 7. 判断5 — データが溜まり始めるタイミング

**判定: ピークが中盤以降。開場直後は推薦に使えるデータがない。初期はランダム提示で凌ぐ設計が必要。**

| 指標 | 金(10/10) | 土(10/11) |
|---|---|---|
| 最初のチェックイン | 09:30 | 09:30 |
| 最後のチェックイン | 17:00 | 15:00 |
| **新規流入のピーク** | **13:30**（43名／開場4.0時間後） | 11:00（31名／開場1.5時間後） |
| 同時滞在人数のピーク | 14:30（89名） | 12:00（52名） |
| **推薦フォールバック解除時刻** | **11:34**（開場から125分） | 10:56（開場から86分） |

「推薦フォールバック解除」= 去年のアプリが持っていた
「チェックイン実績者が20人以下なら完全ランダム推薦」の閾値に到達した時刻。

**今年の設計への含意**: 金曜開催なら、**開場から約2時間は個人化推薦が動かせない**。
この間をどう埋めるか（人気度ベース／ランダム／固定おすすめ）を先に決める必要がある。

新規流入ピーク(13:30)と同時滞在ピーク(14:30)に**1時間のズレ**がある。
滞在人数が最大になる時間帯には、既にデータが十分溜まっている。

## 8. 補助的な判断材料

### 推薦マスは実際に踏まれたか

| 指標 | 値 |
|---|---:|
| 推薦マスのチェックイン率 | **35.4%** |
| ランダムマスのチェックイン率 | **27.0%** |
| 差 | **+8.4 ポイント** |
| 推薦マス総数 / ランダムマス総数 | 912枠 / 3,776枠 |

**判定: 去年の推薦は機能していた。同方式を踏襲してよい。**

ただし**制約3**（位置効果との交絡）により、この+8.4ptが推薦アルゴリズムの効果なのか
中央4マスの視認性の効果なのかは分離できない。
今年もし推薦マスをランダムな位置に置けば、この交絡を解消した測定ができる。

### ビンゴの達成度

| 指標 | 値 |
|---|---:|
| 達成マス数の中央値 | 3 / 16 |
| 4ライン達成率（完走の定義） | 14.9% |

### 事後アクションの回収率（アンケートの代理指標）

| 指標 | 値 |
|---|---:|
| 投票確定率 | **36.4%**（110 / 302名） |

アンケート機能が存在しないため、アワード投票の確定を「事後アクション」の代理とする。
**今年の評価入力の回収率は36%程度を見込むのが妥当。**

## 付記: この結果の再現方法

```bash
python src/run_pipeline.py          # data/raw/ の最新ダンプから再生成
streamlit run src/dashboard.py      # 絞り込みながら確認
```

**`--exclude-pids` に根拠のない pid を渡さないこと。**
本サマリの初版は、ドキュメントの記述例に含まれていた `u0007 u0042` が
実際に除外された状態で算出されており、一般参加者2名が誤って落ちていた。
除外候補は `dashboard.py` の「除外候補」タブ、または
`python src/build_tables.py <dump> --show-staff-candidates` で確認する。
