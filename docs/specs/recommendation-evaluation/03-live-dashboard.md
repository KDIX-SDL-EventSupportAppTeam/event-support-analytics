### 対応行動を画面に印字する

**当日は手順書を読み返す余裕が無い。**
各指標の隣に、上表の「何をするか」をそのまま短文で表示する。

### `/ops/state` が取れないとき

該当欄を「**取得不能**」と表示し、**他の指標は動かし続ける**。
`/ops/state` の取得失敗そのものが、フォールバック率と併せて障害のサインになる。

ただし **401 / 403（認証エラー）だけは「取得不能」と区別して表示する**。
本番の `/ops/*` は `X-Ops-Token` による認証が必須
（`event-support-recommend` ADR 0008）で、
analytics 側がトークンを送らなければ 401 が返り続ける。これは**こちら側の設定漏れ**であり、
「推薦エンジンが落ちている」とは打つ手がまったく違う。両者が同じ「取得不能」に丸まると
当日の切り分けができない。認証エラー時は「`RECOMMEND_OPS_TOKEN` を確認」と明示する。

- ヘッダは `X-Ops-Token`。`Authorization` は使わない（Cloud Run の IAM 認証と層を分ける）
- トークンは環境変数 `RECOMMEND_OPS_TOKEN`（推薦サービスの `OPS_TOKEN` と同一の秘密）
- base URL は環境変数 `RECOMMEND_BASE_URL` を既定にする。当日 URL を手打ちさせない
  （打ち間違いが認証エラー・接続失敗と同じ症状に見える）。サイドバーの入力欄は上書き用に残す

### パラメータ調整画面 `/demo` へのリンク

パラメータ調整のシミュレータ `/demo` は推薦側に置いたまま、この画面から**リンク1本で繋ぐ**
（`event-support-recommend` ADR 0008 案A。Streamlit へ移植し直さない）。
URL は `RECOMMEND_BASE_URL` から組み立てる。リンクの近くに必ず注記を置く:

- **シミュレータである。** 本番設定は Cloud Run の env が正で、変更にはデプロイが必要
- 開くには `RECOMMEND_OPS_TOKEN` が要る（この画面の合言葉とは別）

## 2. 画面2 — 当日の時系列

**1枚のグラフに重ねて描く。別々のグラフにしてはならない**
（[analytics-pipeline の B-2/B-3](../analytics-pipeline/05-visualization/chart-spec.md) と同じ流儀）。

```
横軸: 時刻（JST・10分刻み）
縦軸: 件数

 ── 累計チェックイン
 ── 累計評価
 ── 決定表件数
 ┈┈ しきい値の水平線（30 / 60）
 │  フェーズが切り替わった時刻の縦線
 │  品質ゲートを通過した時刻の縦線
 │  設定を変更した時刻の縦線（変更した場合）
```

- 当日は「予定どおり育っているか」の確認に使う
- **事後はそのまま論文の図になる**（「データが溜まるにつれて戦略が切り替わった」の直接の証拠）
- **設定を変更したら必ず縦線を引く。** 前後を別データとして扱うために要る

## 3. 画面3 — 異常検知

| 検知 | 算出 | 意味 |
|---|---|---|
| **割当されたブースの集中度** | `recommendation_scores` で `was_assigned=1` のブース別件数の分布（上位1件の占有率、ジニ係数など） | **人気順への退化の実地検出。** このアプリの失敗の定義そのもの |
| 空マス | `bingo_cells` で `is_revealed=1 AND booth_id IS NULL` | 候補切れ（E7） |
| 未修復のカード | 解放イベントがあるのに該当マスが `is_revealed=0` | 自己修復が働いているか |
| カード外訪問の割合 | `check_ins.cell_id IS NULL` の割合 | 参加者がカードを無視していないか |

**1つ目が最も重要。** 「人気順に退化していないこと」はテストで禁止しているが、
**本番データで実地に確認できるのはここだけ**である。

特定のブースが全体の割当の大半を占めていたら、何かがおかしい。

## 5. 当日に表示してはいけないもの

> **A/B の効果（DRSA 枠と COVERAGE 枠の訪問率の差）を当日に表示しない。**

見てしまうと、「DRSA のほうが悪いから設定を変えよう」という判断をしたくなる。
それをやると**実験が壊れる**（途中で条件を変えたデータは比較できない）。
**無意識にやってしまうのが怖い。**

| | |
|---|---|
| ✅ 表示してよい | 各群の**提示数**（§4） |
| ❌ 表示しない | 訪問率、およびその**差** |

効果は当日の行動に何も影響しない。**隠しても失うものが無い。**

実装上も、当日画面のコードに訪問率の群別集計を**書かない**。
「あとで見ないようにする」ではなく、**最初から計算しない**。
