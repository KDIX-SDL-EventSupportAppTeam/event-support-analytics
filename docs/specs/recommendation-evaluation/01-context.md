## 2. 実験設計の要約（Q2 のため）

### なぜ参加者どうしを比べてはいけないか

フェーズは決定表の件数で決まり、件数は時刻とともに増える。したがって

```
11時来場 → COVERAGE     ┐
13時来場 → SIMILARITY   ├─ フェーズ ＝ 来場時刻 ＝ 参加者の性質
15時来場 → DRSA         ┘
```

**「DRSA 群のほうが良かった」は「午後に来た人はもともと違う」と区別できない。**

### 参加者内ランダム化

1回の解放で 2 / 4 / 6 マスが同時に開く。**この枠を2つの戦略で分け合う。**

| 解放 | 枠数 | DRSA | COVERAGE |
|---|---:|---:|---:|
| 1回目 | 2 | 1 | 1 |
| 2回目 | 4 | 2 | 2 |
| 3回目 | 6 | 3 | 3 |

同一人物・同一時刻・同一カードの中での比較なので、**違うのはアルゴリズムだけ。**

**発動は DRSA の品質ゲート通過後のみ。** 規則がまだ出ていない段階で分割しても、
DRSA 枠の中身が COVERAGE へ退避するため比較にならず、少ない標本を削るだけになる。

どちらの群かは `recommendation_scores.attributes.arm` に入る（[02](02-data-source.md)）。

### 標本サイズ（桁感）

| 項目 | 概算 |
|---|---:|
| DRSA 期に到達する参加者 | 100〜120 |
| 各群の提示枠 | **600〜700** |
| 各群の訪問件数 | 100前後 |
| MISMATCH で推薦された枠（Q3 の分母） | 約 600 |
| うち評価が付く（Q3 の分子の母数） | **約 40** |

**検出できるのは 8ポイント程度の差まで。** 3〜5ポイントの差は取れない。
**サブグループ解析（年代別 × フェーズ別など）は成立しない。**

→ 図は「差があるかないか」を示す設計にする。効果量を精密に見せる図は作らない。

## 3. 去年データの位置づけ

**去年データは今年の対照群にならない。** 推薦アルゴリズム以外が変わりすぎている。

| 変わったもの | 去年 | 今年 |
|---|---|---|
| **ビンゴの仕組み** | 16マスを最初に全部配る | **中央4マスから段階的に開放** |
| 推薦のタイミング | 初回ログイン時に1回 | 解放のたびに最大3回 |
| 推薦マスの位置 | 中央4マス固定 | 参加者ごとに違う |
| **評価機能** | **存在しない** | 星4段階 |
| ブース | 40件（別の出展者） | 別構成 |
| 開催 | 2日間 | 1日 |

「今年は推薦マスへの訪問率が上がった」と言っても、
**「後出し方式にしたからでは?」で崩れる。**

さらに**去年はブース単位の評価が1件も存在しない**（[FINDINGS.md](../../FINDINGS.md) §9）ため、
セレンディピティ指標そのものを去年について計算できない。

### それでも有効な4つの用途

| # | 用途 | 対応する図・作業 |
|---|---|---|
| ① | **Q1（周遊促進）の比較** | [04](04-post-analysis.md) 図①。仕組みの変更込みで評価するのが正しいので正当 |
| ② | **自発訪問での不一致率の基準値** | §3.1 のカテゴリ付与が前提 |
| ③ | **先行研究の限界の提示** | 去年も同じカード内比較で +8.4pt を得たが位置効果と分離できなかった。**今年はそれを構造的に解決した**という筋書き |
| ④ | **事前シミュレーション** | §4 |

### 3.1 去年ブースへのカテゴリ付与（②の前提）

去年のデータには参加者の興味ジャンル（8区分・単一選択）はあるが、
**ブース側にカテゴリが無い**（[booths.csv](../../../data/tables/) に列が無い）ため突き合わせができない。
ブースは40件なので手作業で付与できる。

**バイアス防止のための手順**

- **今年のカテゴリが確定してから行う**（分類体系を揃えるため）
- **結果を見る前に付与を完了させる。** 結果を見てから分類を調整しない
- 付与規則を文書化し、可能なら複数人で独立に付けて一致率を確認する

**限界**: 去年は評価が無いので「行った」までしか言えず「気に入った」は言えない。
去年の興味ジャンルは単一選択・今年は複数選択なので、定義を揃える工夫が要る。

### 3.2 去年データの再解析（可能性・要検証）

去年の枠数は `推薦マス 912 / ランダムマス 3,776 / 合計 4,688`（293名 × 16マス）。
推薦マスは1人4枠なので **912 ÷ 4 = 228名**。
つまり **293名中65名は中央4マスもランダム**だった可能性がある
（フォールバック解除 11:34 より前にカードを作った層）。

もしそうなら**位置を固定したまま推薦の有無だけを比較できる**かもしれず、
去年の +8.4pt から位置効果を剥がせる可能性がある。

ただし**この65名は「朝早く来た人」なので、今年と同じ時刻の交絡が入る。**
完全には解決しない。

> **上記の 228 / 65 は合計値からの推測である。実データでの検証が必要。**

## 4. 事前シミュレーション（イベント前にやる）

**本リポジトリが担当するのが自然である**（去年データを持っているため）。

去年の来場分布・訪問間隔・評価回収率を使って当日を再現し、次の1点を確かめる。

> **DRSA は何時に、何人に対して、どんな品質で発火するのか。**

現状これは去年データからの**推定しかない**。実際に走らせて確認する。

ここで「一日中 γ が低く規則が1本も出ない」と分かれば、**イベント前に手を打てる**
（条件属性の定義を変える、一貫性水準を見直す、品質ゲートのしきい値を調整する）。

出力は、推薦側の品質ゲートのしきい値（暫定: 規則3本・γ 0.5・被覆率 0.5）の根拠になる。
