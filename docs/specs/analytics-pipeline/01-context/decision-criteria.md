# 判断基準

分析の目的は「数字を出すこと」ではなく「設計判断を決めること」である。
**算出前にしきい値を決めておく**ことで、結果を都合よく解釈する余地をなくす。

各指標がどの値になったら、どう判断するかを事前に固定する。

---

## 判断1: 参加者の典型像は「短時間・数ブース」か「長時間・多ブース」か

**根拠となる指標**: A-1（滞在時間ヒストグラム）、A-3（30分未満の割合）、C-1（訪問ブース数分布）

| 条件 | 判断 |
|---|---|
| 30分未満が **50%以上** | 短時間層が多数派。推薦アルゴリズムの精緻化より「短時間滞在者をどう扱うか」が主論点 |
| 30分未満が **20〜50%** | 二層構造。短時間層と長時間層で別々の体験設計が要る |
| 30分未満が **20%未満** | 長時間滞在が標準。推薦の作り込みに投資する価値がある |

分布が**二峰性**を示した場合は、割合にかかわらず層別設計を検討する。

---

## 判断2: 今年のデータ件数規模

**根拠となる指標**: F-1（日別登録者数）、C-2（訪問ブース数の中央値）

算出式:

```
今年の想定チェックイン数 = 今年の想定参加者数 × 去年初日の1人あたり中央値
```

**注意**: 去年の総数302名・2,141件は2日間の値である。
必ず**初日のみの値**に分解してから外挿すること。

| 条件 | 判断 |
|---|---|
| 想定 **1,000件以上** | 協調フィルタリングが機能する程度のデータ量。推薦の作り込みは妥当 |
| 想定 **300〜1,000件** | 限界的。単純な人気度ベースの推薦に留めるべき |
| 想定 **300件未満** | 個人化推薦は成立しない。ルールベースで設計する |

---

## 判断3: 推薦が届く対象は誰か

**根拠となる指標**: チェックイン0件ユーザーの割合、A-4（単発訪問者の割合）、C-3（滞在時間と訪問数の相関）

推薦は「2件目以降のチェックイン」でしか意味を持たない。
したがって以下の層には**構造的に届かない**。

- チェックイン0件のユーザー（アプリを開いたが一度も使わなかった層）
- 単発訪問者（1ブースのみ）

| 条件 | 判断 |
|---|---|
| 上記2層の合計が **40%以上** | 推薦機能より先に「使われない問題」を解くべき。オンボーディング設計が優先 |
| 合計が **20〜40%** | 推薦は有効だが、初回体験の改善と並行して進める |
| 合計が **20%未満** | 推薦機能に集中してよい |

---

## 判断4: ブース間の訪問偏りへの対策コスト

**根拠となる指標**: D-2（最多／最少の倍率）、D-3（上位20%の占有率）

| 条件 | 判断 |
|---|---|
| 倍率 **5倍以上** | 偏りは深刻。回遊の誘導に工数を割く価値がある |
| 倍率 **2〜5倍** | 中程度。推薦アルゴリズムの副作用として緩和を狙う程度でよい |
| 倍率 **2倍未満** | 偏りは小さい。過剰な制御は不要 |

D-3 が **50%以上**（上位20%のブースが全訪問の半数以上を占める）なら、
倍率にかかわらず対策対象とする。

---

## 判断5: データが溜まり始めるタイミング

**根拠となる指標**: B-2（30分刻みの新規参加者数）、B-3（同時滞在人数）

| 条件 | 判断 |
|---|---|
| 開場後 **1時間以内**に新規流入がピーク | 「開場直後にデータを集めきる」設計が成立する |
| ピークが **中盤以降** | 開場直後は推薦に使えるデータがない。初期はランダム提示で凌ぐ設計が必要 |
| 流入が**終日ほぼ平坦** | 「いつでも新規が来る」前提。推薦は常に不完全なデータで動く覚悟が要る |

去年のアプリは「チェックイン実績のあるユーザーが20人以下なら完全ランダム推薦」という
フォールバックを持っていた（`app.py` の `get_realtime_recommendations`）。
この閾値20人に**何時何分に到達したか**を算出することで、
今年の推薦起動タイミングを直接設計できる。

## 補助的な判断材料

### 推薦マスは実際に踏まれたか

`bingo_card` に `is_recommendation` フラグが保存されているため、
**推薦されたマスとランダムなマスで、チェックイン率に差があったか**を検証できる。

| 条件 | 判断 |
|---|---|
| 推薦マスのチェックイン率がランダムマスより**有意に高い** | 去年の推薦は機能していた。同方式を踏襲してよい |
| **差がない、または低い** | 去年の推薦は効いていない。方式そのものを見直す必要がある |

これは去年データから引き出せる最も直接的な「推薦の効果測定」であり、
今年のアルゴリズム選定に対する最も強い根拠になる。
