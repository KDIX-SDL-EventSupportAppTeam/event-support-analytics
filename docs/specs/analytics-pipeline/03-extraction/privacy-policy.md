# プライバシー方針

## 原則

**分析に不要な個人情報は、取得しない。取得したものは即座に破棄する。**

去年のデータには実在する302名のメールアドレスと、
そのパスワードハッシュが含まれている。分析にはどちらも不要である。

## 具体的な扱い

### パスワードハッシュ

**取得しない。**

`users` コレクションの `password_hash` フィールドは、抽出スクリプトで明示的に除外する。
bcrypt ハッシュであり直ちに解読可能ではないが、
**分析上まったく用途がないものを手元に置く理由がない。**

### メールアドレス

**取得はするが、即座に仮名IDへ置換し、破棄する。**

メールアドレスはドキュメントIDそのものであるため、取得を回避できない。
そのため、スクリプト内で以下の処理を行う。

1. 全ユーザーのメールアドレスを取得し、ソートする
2. ソート順に `u0001` から連番の仮名IDを割り当てる
3. 全レコードのメールアドレス参照を仮名IDに置換する
4. **メールアドレスはファイルに書き出さず、プロセス終了とともに破棄する**

**対応表（メールアドレス ↔ 仮名ID）は生成しない。**
これは意図的な決定である。生成しないことで、
後から個人を再特定する経路そのものを断つ。

この決定は以下の分析を放棄することを意味するが、いずれも不要と確認済みである。
- 特定ユーザーの追跡
- 今年のデータと突き合わせたリピーター分析

### 仮名IDの性質

仮名IDはメールアドレスのソート順で決まるため、**決定的**である。
同じデータから再抽出すれば同じIDが割り当てられる。

一方で、仮名IDから元のメールアドレスを復元することはできない
（対応表を保持しないため）。

なお、メールアドレスのソート順に依存するため、
**仮名IDの順序にはわずかな情報が残る**（アルファベット順の位置）。
分析上この順序に意味を持たせてはならない。

## リポジトリへのコミット禁止事項

以下は `.gitignore` で除外し、**絶対にコミットしない**。

```gitignore
# データ本体
data/

# 認証情報
*.json.key
service-account*.json
.env
```

private リポジトリであっても、
302名分の行動履歴をバージョン管理下に置くべきではない。
組織メンバー全員がアクセスできてしまうこと、
および一度コミットすると履歴から消すのが困難であることが理由。

**分析結果（集計値・グラフ）はコミットしてよい。**
個人が特定できない粒度に集約されているため。

ただし集計値であっても、
**セルの該当人数が極端に少ない集計（1〜2名）は公開資料に含めない**こと。
属性の組み合わせから個人が推定されうる。

## 去年のリポジトリで発見した問題（参考）

引き継ぎ元 `HidetsuguSuto/2025_P3_supporters_game` には、
以下が平文でコミットされている。

- Gmail アプリパスワード（`MAIL_PASSWORD`）
- Flask のセッション暗号化キー（`SECRET_KEY`）
- 管理者パスワード（`ADMIN_PASSWORD`）

`backend/app.yaml` および `README.md` の両方に記載がある。

**本リポジトリでは同じ過ちを繰り返さない。**
認証情報は環境変数または ADC で扱い、リポジトリには含めない。

なお去年のリポジトリ側の対処（シークレットのローテーション、履歴の書き換え）は、
本リポジトリの作業者が admin 権限を持たないため実施できない。
引き継ぎの一環として所有者へ報告すべき事項である。

## 去年のアプリに存在する脆弱性（参考）

`app.py` のエクスポートエンドポイント `/api/admin/export_users` には
`@token_required` デコレータが付いていない。

管理者認証なしで全ユーザーのメールアドレスを取得できる状態にある。
アプリが稼働中であれば対処が必要。
本リポジトリの作業範囲外だが、報告事項として記録しておく。
