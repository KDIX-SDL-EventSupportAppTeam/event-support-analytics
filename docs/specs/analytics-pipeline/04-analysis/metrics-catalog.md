# 指標カタログ

全指標の定義・算出式・実現可否。

**「主分析日」列の意味**（根拠は [confounders.md](confounders.md) 交絡2）:
- **金** = 初日（2025-10-10）。今年が金曜開催のため代表性が高い
- **土** = 2日目（2025-10-11）。クールタイム値が一定で交絡がない
- **両** = 両日を併記

---

## A. 滞在時間の分布【最優先】

**算出の基礎**: `participants.dwell_min`（= `last_ts − first_ts`、分）

| ID | 指標 | 算出方法 | 主分析日 | 可否 |
|---|---|---|---|---|
| A-1 | 滞在時間ヒストグラム | 30分刻み。単発訪問者は除外 | 金 | 可 |
| A-2 | 中央値 / 平均 / Q1 / Q3 | 単発訪問者を除外して算出 | 両 | 可 |
| A-3 | **30分未満の割合** | 単発訪問者を分母に含める | 金 | 可 |
| A-4 | 単発訪問者の人数と割合 | `is_single == true` の件数 | 両 | 可 |
| A-5 | 3時間以上の割合 | `dwell_min >= 180` | 金 | 可 |

### 注意

- **A-3 が最重要指標**。判断1を直接決める（[decision-criteria.md](../01-context/decision-criteria.md)）
- 算出値は**真の滞在時間の下限**である（[confounders.md](confounders.md) 交絡3）
- A-2 は単発訪問者（`dwell_min = 0`）を除外する。含めると分布が歪む
- A-3 は**分母に単発訪問者を含める**。「短時間で帰った層」の実態を示すため

## B. 時間帯別の人の流れ【最優先】

**算出の基礎**: `visits.ts_jst` を30分ビンに丸める

| ID | 指標 | 算出方法 | 主分析日 | 可否 |
|---|---|---|---|---|
| B-1 | チェックイン総件数の推移 | ビンごとの `visits` 件数 | 両 | 可 |
| B-2 | 新規参加者数の推移 | ビンごとの `first_ts` 該当者数 | 金 | 可 |
| B-3 | 同時滞在人数の推移 | `first_ts <= t <= last_ts` を満たす人数 | 金 | 可 |
| B-4 | ピーク時間帯の特定 | B-1 / B-2 / B-3 の最大値の位置 | 両 | 可 |

### 追加指標: 推薦フォールバック解除時刻【重要】

去年のアプリは「チェックイン実績のあるユーザーが20人以下なら完全ランダム推薦」
というフォールバックを持っていた。

> **チェックイン実績者数が20人に到達した時刻**を算出する

これは今年の推薦起動タイミングを設計するための、
最も直接的な数字である。判断5に直結する。

### 注意

- B-3 は定義上、初回チェックイン前と最終チェックイン後が不可視。図に注記すること
- B-2 と B-3 は**必ず同一時間軸に重ねて描く**（[chart-spec.md](../05-visualization/chart-spec.md)）

## C. 訪問ブース数の分布

| ID | 指標 | 算出方法 | 主分析日 | 可否 |
|---|---|---|---|---|
| C-1 | 訪問ブース数ヒストグラム | 1件刻み。**0件から開始** | 金 | 可 |
| C-2 | 中央値 / 平均 | `participants.n_booths` | 両 | 可 |
| C-3 | 滞在時間との相関（散布図） | `dwell_min` × `n_booths`、回帰直線1本 | 金 | 可 |
| C-4 | 達成マス数の分布と完走率 | `n_card_hit` / `bingo_lines` | 両 | 可 |

### 注意

- **C-1 は必ず0件から始める。** チェックイン0件ユーザーが見えなくなる
- C-3 の回帰からは**単発訪問者を除外する**。原点付近に張り付き傾きを歪める
- C-3 の傾き（ブース/時間）が、今年の規模見積もりで最も再利用される数字
- 完走率は「16マス全達成」ではなく「4ライン達成」で定義する
  （去年のアプリはコイン付与を4ラインで打ち切っていたため）

### 追加指標: 推薦マスの効果測定【最重要級】

`bingo_card.is_recommendation` を用いて、次を算出する。

> **推薦マスのチェックイン率 vs ランダムマスのチェックイン率**

```
推薦マス率   = Σ n_rec_hit / Σ n_rec_total
ランダムマス率 = Σ (n_card_hit − n_rec_hit) / Σ (n_card − n_rec_total)
```

**去年データから得られる唯一の直接的な推薦効果の測定である。**
今年のアルゴリズム選定に対する最も強い根拠になる。

なお推薦マスは中央4マス（position 5, 6, 9, 10）に配置されていたため、
**位置の効果と推薦の効果が交絡している。**
中央マスが単に目立つから踏まれた可能性を排除できない。
結論にはこの限界を明記すること。

## D. ブース別訪問者数の偏り

| ID | 指標 | 算出方法 | 主分析日 | 可否 |
|---|---|---|---|---|
| D-1 | ブース別訪問者数の順位表 | `visits` を `booth_id` で集計 | 両 | 可 |
| D-2 | 最多 / 最少の倍率 | 最大値 ÷ 最小値 | 両 | 可 |
| D-3 | 上位20%の占有率 | 上位8ブースの訪問数 ÷ 全訪問数 | 両 | 可 |
| D-4 | 入口からの距離との関係 | 座標の手入力が必要 | 両 | **条件付き** |
| D-5 | 少数ブースの共通点 | 定性分析 | — | **定量化不可** |

### 注意

- D-2 の分母が0になる場合（訪問者0のブース）は、倍率ではなく差で報告する
- **D-4 は D-1〜D-3 で偏りを確認してから着手する。** 偏りが小さければ不要
  （[unavailable-data.md](../02-data-source/unavailable-data.md)）
- D-5 は `booth_description` を読む定性判断。自動化しない

## E. 訪問順序と時間の使い方

| ID | 指標 | 算出方法 | 主分析日 | 可否 |
|---|---|---|---|---|
| E-1 | **1件目に訪問されたブースの分布** | `visit_seq == 1` の `booth_id` 集計 | 金 | 可 |
| E-2 | チェックイン間隔の中央値 | `gap_min` の中央値 | **土** | 条件付き |
| E-3 | 時間帯によるペース変化 | ビン別の `gap_min` 中央値 | **土** | 条件付き |
| E-4 | 同一ブースへの複数回チェックイン | — | — | **不可能（常に0）** |

### E-2 / E-3 が「条件付き」である理由

クールタイム設定が下限として効いているため。
[confounders.md](confounders.md) 交絡1 の手順で
**交絡の大きさを先に測定してから**解釈すること。

床に張り付いた間隔の割合が大きい場合、
E-2 は「下限値」としてのみ報告し、E-3 は結論を出さない。

### E-4 について

`checkins` のドキュメントIDがブースIDであるため、再訪問は記録されない。
**確認するまでもなく常にゼロであるため、この項目は削除する。**

### E-1 の重要性

「最初の1件を自由に選ばせるか、推薦するか」の判断に直結する。
特定ブースへの集中度が高ければ、初回訪問の誘導に意味がある。

## F. 補助指標

| ID | 指標 | 算出方法 | 可否 |
|---|---|---|---|
| F-1 | 総参加者数の実績 | **日別**の登録者数・チェックイン実績者数 | 可 |
| F-2 | 属性分布と滞在時間の相関 | `age` / `gender` / `genre` × `dwell_min` | 条件付き |
| F-3 | リピーター率 | — | **不可能（対象外）** |
| F-4 | 事後アンケート回収率 | 投票確定率で代用 | 代用可 |
| F-5 | 出展ブース数の実績 | **40**（確定済み） | 完了 |

### F-1 の注意

**302名は2日間の延べ人数である。** 今年の見積もり（150〜200名）と
直接比較してはならない。必ず日別に分解すること。

あわせて以下を報告する。
- 日別の登録者数
- 両日参加者の人数
- チェックイン0件の人数
- ビンゴカード未生成の人数（実測8名、テストデータ除外後に再算出）

### F-2 の注意

職業属性（学生 / 社会人 / 家族連れ）は収集されていない。
年代（`age`）を代理指標とするが、解像度は大きく落ちる。

**属性の組み合わせで該当者が1〜2名になるセルは公開資料に含めない**
（[privacy-policy.md](../03-extraction/privacy-policy.md)）。

### F-4 の代用

```
投票確定率 = vote_finalized == 1 の人数 ÷ 参加者数
```

実測では 123 / 302 = **40.7%**（テストデータ除外前）。
今年の評価入力の回収率を見積もる基礎として使う。

## 算出の順序

```
1. クールタイムの床の検出        ← 交絡1。他のすべての前提
2. 日別の基礎集計（F-1）          ← 規模感の把握
3. A（滞在時間）                  ← 判断1
4. C-1 / C-3（訪問ブース数）      ← 判断2・3
5. B（時間帯）                    ← 判断5
6. D-1〜D-3（偏り）               ← 判断4
7. E-1（初回訪問）
8. 推薦マスの効果測定
9. 必要に応じて D-4 / F-2
```
